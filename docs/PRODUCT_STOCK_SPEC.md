# Product Stock Specification

## 1. Модель доступности

`stock` и `isAvailable` решают разные задачи:

- `stock = null`: количественный учёт отключён. Подходит для услуг, кофе, стрижек и товаров без точного складского учёта.
- `stock > 0` и `isAvailable = true`: позиция видна клиенту и доступна для заказа.
- `stock = 0` и `isAvailable = true`: позиция видна с текстом `Нет в наличии`, кнопка добавления заблокирована.
- `isAvailable = false`: позиция скрыта от клиента независимо от `stock`, но видна продавцу.
- `archivedAt != null`: позиция архивная, скрыта от клиента и обычных seller-фильтров, но доступна продавцу через фильтр `Архив`.

Отрицательный `stock` запрещён.

## 2. Режимы seller UI

`Считать остатки`
- `stock` обязателен как целое число `>= 0`.
- Доступны быстрые действия `-1`, `+1`, `Изменить количество`.

`Просто в наличии / нет`
- `stock = null`.
- Доступность управляется только `isAvailable`.

Переключение из количественного режима в простой устанавливает `stock = null`. Обратное переключение требует начальное количество.

## 3. Checkout

Перед созданием заказа сервер обязан повторно прочитать позиции из БД и проверить:

- позиция принадлежит текущему бизнесу;
- `archivedAt = null`;
- `isAvailable = true`;
- для `stock != null` остатка достаточно для суммарного количества позиции в корзине.

Проверка и списание выполняются в одной транзакции. Повторяющиеся строки одной позиции сначала агрегируются.

Если остатка недостаточно:

- заказ не создаётся;
- stock не меняется;
- API возвращает стабильный код `INSUFFICIENT_STOCK`;
- клиент получает список закончившихся позиций и понятный текст без Prisma-ошибок.

## 4. Списание и возврат

- Количественный stock списывается один раз при успешном создании заказа.
- `stock = null` никогда не списывается.
- Повторный HTTP-запрос не должен создавать отрицательный остаток.
- При первой отмене заказа до выполнения зарезервированный stock возвращается один раз.
- Повторная отмена не возвращает stock повторно.

## 5. Snapshot

`OrderItem` хранит `name`, `price`, `quantity` и опциональную ссылку `itemId`.

- Новая цена действует только для новых заказов.
- Архивирование/переименование товара не меняет старый заказ.
- Отсутствие связанного `Item` не мешает показать историю заказа.
