# Production MVP Manual QA

## Before Testing

- [ ] Применён `docs/manual-stabilize-checkout-analytics-agent.sql` в Supabase.
- [ ] В production заданы корректные `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_WEBAPP_URL` и `TELEGRAM_WEBHOOK_URL`.
- [ ] `DATABASE_URL` использует Supabase transaction pooler, а `DIRECT_URL` — прямое подключение.
- [ ] Telegram URL не содержит `localhost`, `127.0.0.1` или ngrok.

## Telegram And Marketplace

- [ ] Выполнить `/start` в production-боте.
- [ ] Открыть Mini App из Telegram.
- [ ] Убедиться, что skeleton быстро появляется, а список магазинов загружается без пустого экрана.
- [ ] Спросить бота: `Какие магазины есть?` и проверить список активных магазинов с кнопками.
- [ ] Спросить: `Есть шоколад?` без выбранного магазина и проверить поиск по всем активным магазинам.
- [ ] Спросить: `Что есть до 500 рублей?` и проверить ценовой фильтр.
- [ ] Проверить, что отсутствующий товар отвечает `Не нашёл это в каталоге`.
- [ ] Проверить товар с `stock=0`: агент сообщает, что он есть в каталоге, но отсутствует в наличии.
- [ ] Выбрать `Мир Кондитера`, повторить вопрос и проверить поиск только в этом магазине.
- [ ] Спросить `Сколько доставка в Гойты?` и проверить конкретную зону или ответ `Для этой зоны доставка не настроена`.
- [ ] Спросить `Можно самовывоз?` и проверить `pickupEnabled`.
- [ ] Спросить про часы работы и контакты выбранного магазина.
- [ ] Спросить `Какие записи у меня есть?` и проверить только собственные записи.
- [ ] Проверить, что кнопки агента открываются как Telegram WebApp.

## Checkout And Payment

- [ ] Добавить доступный товар в корзину и пройти checkout.
- [ ] Двойной клик по созданию заказа не создаёт дубль.
- [ ] При медленном повторном запросе с тем же `idempotencyKey` сервер возвращает существующий заказ.
- [ ] Загрузить чек перевода.
- [ ] Клиент и продавец видят `Ожидает проверки продавцом`.
- [ ] Продавец видит ожидаемую сумму и кнопку `Открыть чек`.
- [ ] В интерфейсе нет AI-статуса, процентов, распознанной суммы или AI-комментария.
- [ ] Продавец подтверждает оплату кнопкой `Подтвердить оплату`.
- [ ] Повторное подтверждение или отклонение показывает `Оплата уже обработана продавцом`.
- [ ] Отклонение оплаты отменяет заказ и возвращает учтённый остаток.

## Orders And Courier

- [ ] Продавец видит последние 20 заказов и может нажать `Загрузить ещё`.
- [ ] Назначить курьера.
- [ ] Курьер принял заказ.
- [ ] Курьер отметил `Забрал`.
- [ ] Курьер отметил `В пути`.
- [ ] Курьер отметил `Доставил`.
- [ ] Клиент видит историю заказа и актуальный статус.

## Seller Panel

- [ ] Список товаров не выходит за ширину мобильного экрана.
- [ ] Название переносится, изображение не искажается, edit/delete доступны.
- [ ] Фильтр товаров открывается как bottom sheet, без Android native select.
- [ ] Добавить товар в режиме `Просто наличие`.
- [ ] Добавить товар в режиме `Считать остаток`.
- [ ] Товар с `stock=0` автоматически недоступен и не покупается.
- [ ] Товар с `stock>0` доступен, после заказа остаток уменьшается.
- [ ] Отмена заказа возвращает остаток ровно один раз.
- [ ] Редактор зоны доставки открывается как кастомный bottom sheet.
- [ ] Дата записи выбирается кастомным bottom sheet, время выбирается кнопками.

## Reviews

- [ ] Применён `docs/manual-add-business-reviews.sql`.
- [ ] Завершённый заказ показывает `Оставить отзыв`.
- [ ] Незавершённый или чужой заказ не позволяет создать отзыв.
- [ ] Нельзя отправить рейтинг 0 или 6.
- [ ] Повторный отзыв на тот же заказ или booking отклоняется.
- [ ] Рейтинг и количество обновляются на карточке и внутри бизнеса.
- [ ] Продавец видит отзыв без кнопки удаления.
- [ ] Super Admin скрывает отзыв; после скрытия он исчезает из публичного списка и рейтинга.

## Analytics

- [ ] Открыть аналитику продавца.
- [ ] Отменённые и отклонённые заказы не входят в выручку.
- [ ] Отменённые заказы показаны отдельным блоком.
- [ ] Средний чек рассчитан только по валидным оплаченным заказам.
- [ ] Конверсия имеет понятное пояснение.
- [ ] Топ товаров соответствует количеству проданных единиц из валидных заказов.
