# Delivery Flow Specification

## 1. Заказ

Базовый workflow:

`NEW -> ACCEPTED -> PREPARING -> READY -> DELIVERING -> COMPLETED`

Courier workflow:

`ASSIGNED -> ACCEPTED_BY_COURIER -> PICKED_UP -> DELIVERED`

Продавец назначает курьера после готовности или подготовки заказа. Курьер получает Telegram-уведомление.

## 2. Права курьера

Курьер видит:

- доступные доставки;
- активные назначения;
- завершённые доставки.

Курьер может:

- принять назначение;
- позвонить клиенту;
- открыть адрес в картах;
- отметить `Забрал у продавца`;
- после этого отметить `Доставил`.

`DELIVERED` запрещён без предыдущего `PICKED_UP`. Повторные клики не создают новые назначения, события или уведомления.

## 3. Зоны доставки

Доменная модель зоны:

- `name`;
- `price` (в текущей БД legacy-поле может называться `fee`);
- `minOrderAmount`;
- `estimatedMinutes`;
- `isActive`;
- `sortOrder`;
- `archivedAt`.

Правила:

- checkout показывает только активные неархивные зоны;
- отключённая зона не доступна для новых заказов;
- использованная зона не удаляется физически, а архивируется;
- название и стоимость зоны сохраняются snapshot в `Order`;
- минимальная сумма проверяется сервером.

Примеры:

- Урус-Мартан центр - 200 RUB;
- Урус-Мартан дальние районы - 250-300 RUB;
- Гойты - 500 RUB;
- Другое - стоимость вручную подтверждает продавец.
