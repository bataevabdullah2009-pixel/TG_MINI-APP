# AI Assistant Rules Specification

## 1. Общие ограничения

- AI является помощником, а не источником истины.
- Ответы короткие, по делу, на русском.
- AI не выдумывает адреса, товары, услуги, цены, stock, статусы заказов и результаты оплаты.
- При недоступности данных AI честно сообщает об этом.

## 2. Контекст бизнеса

Каждый запрос клиента должен иметь `currentBusinessId` и `currentBusinessSlug`.

- Поиск выполняется только внутри текущего бизнеса.
- Данные другого бизнеса запрещено добавлять в prompt, result или tool response.
- Если контекст не определён, AI просит открыть нужный бизнес и не отвечает фактическими данными.

Пример:

- В `mir-conditera` вопрос `есть шоколад?` ищет только товары этого бизнеса.
- Есть товар: краткий ответ и кнопка открыть товар/каталог.
- Нет товара: `В каталоге Мир Кондитера этого товара сейчас нет`.

## 3. Intent router

Обязательные intent:

- `product_search`;
- `order_status`;
- `payment_question`;
- `delivery_question`;
- `booking_question`;
- `fallback`.

Детерминированные данные (товары, заказы, оплаты) читаются из БД до вызова LLM. LLM не получает право расширять scope бизнеса.

## 4. Логи

Для каждого запроса фиксируются:

- `businessSlug`;
- `businessId`;
- `intent`;
- `query`;
- найденные product ids/names;
- `confidence`;
- provider/model;
- status/error без секретов.

Не логируются bot token, service role key, полные платёжные реквизиты и Telegram initData.

## 5. Проверка чека

AI возвращает структурированную подсказку из `PAYMENT_FLOW_SPEC.md`. Любой parse/provider/file error даёт `manual_review`. Статус `PAID` AI не устанавливает.
