# Payment Flow Specification

## 1. Способы MVP

- `CASH`
- `TRANSFER`

Другие enum-значения не считаются доступными клиенту MVP без отдельной интеграции.

## 2. TRANSFER

1. Клиент видит банк, телефон/реквизиты, получателя и инструкции продавца.
2. Клиент загружает JPG/JPEG/PNG/WEBP или PDF.
3. Заказ получает `paymentStatus = AWAITING_REVIEW`.
4. Продавец видит ожидаемую сумму и ссылку `Открыть чек`.
5. Продавец вручную выбирает `Подтвердить оплату` или `Отклонить оплату`.
6. Только подтверждение продавца или webhook реальной платёжной системы устанавливает `PAID`.
7. При отклонении сохраняется причина, клиент получает уведомление.

Автоматической проверки чека нет. Решение по оплате принимает продавец.

## 3. CASH

- Деньги принимает продавец или назначенный курьер.
- Получивший деньги отмечает оплату.
- До этого `paymentStatus = PENDING`.
- При неоплате заказ отменяется или помечается проблемным согласно seller workflow.

## 4. Безопасность

- URL чека создаётся только через разрешённый upload flow.
- Service role key не попадает в клиент.
- Содержимое чека не подтверждает оплату автоматически.
- Повторное подтверждение/отклонение идемпотентно.
