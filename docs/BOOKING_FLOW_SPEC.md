# Booking Flow Specification

## 1. Создание записи

Клиент выбирает активную услугу, дату/время и при необходимости мастера. Сервер проверяет бизнес, услугу, мастера и свободный слот.

Начальный статус: `NEW`/`PENDING`, затем `CONFIRMED`.

## 2. Переходы

- создание;
- подтверждение продавцом;
- перенос с уведомлением клиента;
- отмена клиентом или продавцом;
- `NO_SHOW` для клиента, который не пришёл;
- отдельная причина, если не пришёл мастер;
- `COMPLETED` после оказания услуги;
- `EXPIRED` для необработанной просроченной записи.

Повторный переход не создаёт дубли уведомлений.

## 3. Перенос

- Старый слот освобождается.
- Новый слот проверяется повторно.
- Клиент видит новую дату/время.
- История причины переноса должна быть доступна продавцу.

## 4. Оплата и возврат

- Если запись была оплачена и отменена по правилам возврата, payment переводится в `REFUNDED` только после фактического возврата.
- AI не принимает решение о возврате.
- При отсутствии автоматического refund продавец выполняет возврат вручную и фиксирует результат.

## 5. Связь

Клиент должен иметь кнопку связи с бизнесом. Адрес, телефон и Telegram берутся только из текущего бизнеса и не выдумываются AI.
