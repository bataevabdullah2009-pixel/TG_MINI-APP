# Catalog and Product Specification

## 1. Модель каталога

Каждый бизнес имеет независимые категории и позиции. Позиция имеет тип
`PRODUCT` или `SERVICE`.

Общие поля:

- название;
- описание;
- цена;
- старая цена, если используется;
- изображение;
- категория;
- порядок;
- популярность;
- доступность;
- состояние архива.

Для услуги дополнительно важна длительность. Для товара важен режим остатка.

## 2. Категории

- Категория принадлежит одному бизнесу.
- Название уникально в рамках бизнеса.
- Неактивная категория не должна делать чужую позицию доступной.
- Позиция может временно не иметь категории.
- Порядок должен быть стабильным.
- Создание fallback-категории не должно дублировать существующую.

## 3. Видимость позиции

Клиент видит позицию, если:

- бизнес доступен;
- позиция принадлежит бизнесу;
- позиция не архивирована;
- `isAvailable` разрешает отображение;
- дополнительные правила шаблона не запрещают её.

`stock = 0` и `isAvailable = true` может показывать карточку `Нет в наличии`,
но не разрешает добавление.

## 4. Цена

- Цена неотрицательная и хранится в валюте бизнеса.
- Клиентская цена не является доверенной.
- Checkout повторно читает актуальную цену.
- OrderItem сохраняет цену на момент заказа.
- Изменение цены не меняет старую историю.
- Silent reprice созданного заказа запрещён.

## 5. Товар и услуга

### PRODUCT

- может участвовать в корзине;
- может иметь количественный stock;
- количество агрегируется до проверки;
- может участвовать в промокоде.

### SERVICE

- участвует в booking flow;
- может иметь duration;
- может быть связана с staff;
- не должна автоматически попадать в товарный checkout, если шаблон этого не
  поддерживает.

## 6. Архивирование

- Рабочее удаление означает archive.
- Архивная позиция скрыта от новых операций.
- OrderItem и Booking продолжают показывать snapshot/связанные данные.
- Восстановление снимает archive, но доступность включается явно.

## 7. Изображения

- Загружаются только разрешённым процессом.
- URL должен быть из разрешённого хранилища.
- Ошибка изображения не ломает карточку.
- Секретный storage key не попадает клиенту.

## 8. Поиск

- Поиск выполняется только в текущем бизнесе.
- Неактивные и архивные позиции не появляются в клиентском результате.
- Результаты имеют стабильный порядок.
- Пустой поиск показывает понятное состояние, а не чужие позиции.

## 9. Инварианты

- Нельзя переместить позицию в чужой бизнес обычным редактированием.
- Каталог продавца и клиента различаются по видимости архивных/скрытых позиций.
- История заказов читается даже при удалённой связи с Item.
- AI не создаёт фактическое наличие без записи в каталоге.
