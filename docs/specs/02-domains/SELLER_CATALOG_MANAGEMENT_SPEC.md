# Seller Catalog Management Specification

## 1. Цель

Кабинет позволяет владельцу поддерживать актуальную витрину без прямого доступа
к базе данных.

## 2. Список

Список поддерживает:

- поиск по названию и описанию;
- фильтр активных;
- фильтр доступных;
- фильтр без остатка;
- фильтр скрытых;
- фильтр архива;
- отображение типа, категории, цены, наличия и остатка.

## 3. Создание

Обязательные данные:

- тип;
- название;
- валидная цена;
- режим остатка;
- начальная доступность.

Опционально:

- описание;
- категория;
- изображение;
- длительность услуги;
- популярность;
- начальный stock.

## 4. Быстрые действия

- `+1` и `-1` для tracked stock;
- точное количество;
- изменение цены;
- включение/выключение доступности;
- архивирование;
- восстановление.

Оптимистичное отображение обязано откатываться при серверной ошибке.

## 5. Полное редактирование

- Нельзя изменить business ownership.
- Валидация выполняется и на клиенте, и на сервере.
- Категория должна принадлежать текущему бизнесу.
- Изображение проходит разрешённый upload flow.
- SERVICE duration не должна использоваться как stock.

## 6. Архив

- Кнопка удаления объясняет, что история сохранится.
- API не выполняет physical delete в основном seller flow.
- Архивная позиция не видна клиенту.
- Восстановленная позиция не становится автоматически доступной без явного
  выбора.

## 7. Массовые и опасные операции

Массовое удаление, импорт, изменение всех цен и обнуление склада не входят в
текущий основной сценарий. Их добавление требует preview, подтверждения и
аудита.

## 8. Защита истории

Редактирование каталога не меняет:

- OrderItem;
- уже рассчитанную скидку;
- стоимость доставки старого заказа;
- завершённую запись;
- фактически принятую оплату.
