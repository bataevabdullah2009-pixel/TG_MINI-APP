# RBAC and Permissions

## 1. Роли

- `CUSTOMER` - клиентский marketplace и собственные операции.
- `BUSINESS_OWNER` - полное операционное управление своим бизнесом.
- `MANAGER` - ограниченная обработка заказов и записей своего бизнеса.
- `COURIER` - доставка заказов своего бизнеса.
- `SUPER_ADMIN` - управление SaaS и явный вход в выбранный бизнес.

## 3. Tenant isolation

- Любая бизнес-операция проверяет подтверждённый business scope.
- `businessId` из query/body не является достаточным разрешением.
- Owner и Manager ограничены привязанным бизнесом.
- Courier дополнительно ограничен courier profile и assignment.
- Super Admin обязан явно выбрать бизнес для tenant mutation.
- Customer ownership проверяется по Telegram session и связанной операции.

## 4. Сессии

- Production Telegram flow подтверждает `initData`.
- Legacy admin cookie/token допускается только в существующих admin-сценариях.
- Неактивный пользователь не получает административную сессию.
- Customer и Courier не должны проходить через admin auth.
- Mock login не должен включаться в production.

## 5. Политика по умолчанию

Если разрешение не описано явно, оно запрещено. Новая кнопка не создаёт право:
соответствующая серверная операция обязана отдельно проверить роль и scope.

## 6. Ошибки доступа

- `401` означает отсутствие подтверждённой сессии.
- `403` означает, что пользователь известен, но действие запрещено.
- `404` может использоваться для скрытия чужого ресурса.
- Ответ не раскрывает существование чужих данных и внутренние поля.
