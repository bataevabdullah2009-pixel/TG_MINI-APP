# Acceptance Criteria

## 1. Marketplace

- Общий каталог открывается без seller/admin данных.
- Показываются только доступные бизнесы.
- Поиск и фильтр работают.
- Неизвестный бизнес не открывает demo fallback.
- Ошибка профиля не скрывает публичный каталог.

## 2. Storefront

- Бизнес открывается в собственном контексте.
- Каталог не содержит чужих позиций.
- Архивные и скрытые позиции недоступны.
- Товар без stock нельзя добавить.
- Сервис открывает booking flow.

## 3. Checkout

- Цена, stock, скидка и доставка проверяются сервером.
- Телефон подтверждён.
- Двойной submit не создаёт два заказа.
- Transfer требует разрешённый proof.
- Заказ появляется у клиента и продавца.
- Ошибка Telegram notification не отменяет заказ.

## 4. Seller

- Владелец видит все заказы своего бизнеса.
- Не видит чужой бизнес.
- Может обработать статус.
- Может управлять каталогом без physical delete.
- Может проверить перевод.
- Может настроить доставку, курьеров и промокоды.

## 5. Manager

- Видит только назначенный бизнес.
- Обрабатывает заказы и записи.
- Не меняет зоны, курьеров, промокоды, оплату и SaaS.

## 6. Courier

- Видит только свой business scope.
- Конкурентное принятие защищено.
- Нельзя доставить до получения и состояния в пути.
- Завершение уведомляет участников.

## 7. Super Admin

- Создаёт бизнес и владельца.
- Меняет access status без потери истории.
- Может явно управлять выбранным бизнесом.
- Не использует destructive production reset.

## 8. Telegram и AI

- `/start` или Mini App кнопка открывает production marketplace.
- Business deep link открывает конкретный бизнес.
- Production URL не содержит localhost/ngrok.
- AI не выдумывает факты и не раскрывает чужой заказ.
- Без выбранного бизнеса AI ищет указанный товар по всем активным бизнесам.
- Отсутствующий товар не подменяется общим fallback-ответом.
- Все кнопки AI открывают Telegram Mini App, а не произвольный browser URL.
- Клиентские и seller AI ошибки имеют безопасный fallback.

## 9. Отзывы

- Отзыв создаётся только по собственной завершённой операции.
- Один заказ или одна запись дают не более одного отзыва.
- Рейтинг принимает только целое значение 1-5.
- Marketplace показывает среднее и количество без констант.
- Скрытый Super Admin отзыв не участвует в рейтинге.
- Продавец видит отзывы, но не может удалить или скрыть их.

## 10. Ошибки и стабильность

- Raw Prisma error не показывается.
- `P2022` обрабатывается безопасно.
- Empty state отличается от error state.
- Protected checkout, seller order visibility и bot routing не регрессируют.

## 11. Проверки перед handoff

Когда доступны:

```bash
npm run lint
npm run typecheck
npm run build
npx prisma validate
npx prisma generate
```

Для документационной задачи дополнительно:

- все относительные Markdown-ссылки существуют;
- нет двух канонических спеков одной области;
- status matrix соответствует фактическому коду;
- изменения не включают секреты и generated build artifacts.
