# Favorites, Profile and History Specification

## 1. Избранное

Клиент может сохранять:

- бизнесы;
- товары и услуги.

Для авторизованного Telegram-пользователя сервер является источником
персонального избранного. Local storage может использоваться для быстрого UI и
анонимного просмотра, но не заменяет server state.

## 2. Синхронизация

- Оптимистичное изменение откатывается при ошибке.
- Повторное добавление не создаёт дубль.
- Удаление отсутствующей записи безопасно.
- FavoriteItem должен принадлежать указанному business.
- Клиент не передаёт чужой Telegram id как доказательство ownership.

## 3. Профиль

Показывает:

- отображаемое имя;
- username;
- Telegram id в безопасном пользовательском контексте;
- телефон;
- статус подтверждения;
- доступные переключатели рабочих ролей.

Роль не меняется из клиентского профиля. Переключатель только открывает
разрешённый workspace.

## 4. История

Клиент видит собственные:

- заказы;
- записи;
- бизнес;
- состав и суммы;
- получение;
- payment status;
- courier, если назначен;
- комментарии, предназначенные клиенту;
- текущий статус.

История поддерживает ограниченную загрузку страниц и нормальные empty states.

## 5. Ownership

- История загружается по подтверждённой Telegram session.
- Business filter дополнительно сужает данные, но не расширяет доступ.
- Чужой customerId или telegramUserId из query игнорируется как разрешение.
- Внутренние заметки и admin-only поля не возвращаются.

## 6. Деградация

- Ошибка профиля не скрывает публичный marketplace.
- Без Telegram session история сообщает о необходимости профиля.
- Ошибка одного персонального раздела не ломает остальные.
- Schema drift превращается в безопасное сообщение или fallback.

## 7. Приватность

Контакты клиента передаются только бизнесу, где создана операция, и курьеру в
объёме доставки. Профиль не публикуется в marketplace.
