# Notification Specification

## 1. Назначение

Уведомление дополняет, но не заменяет запись в кабинете и базе. Сбой Telegram
не должен отменять успешный заказ или запись.

## 2. Получатели

- владелец/назначенный admin chat бизнеса;
- клиент операции;
- назначенный или подходящий курьер;
- Super Admin только для отдельных служебных сценариев.

## 3. События

### Продавец

- новый заказ;
- новая запись;
- изменение доставки;
- истечение операции;
- критический результат оплаты при необходимости.

### Клиент

- изменение статуса заказа;
- изменение статуса записи;
- подтверждение или отклонение перевода;
- назначение курьера;
- заказ в пути;
- доставка завершена;
- истечение или отмена.

### Курьер

- новая доступная доставка;
- прямое назначение;
- освобождение assignment;
- отмена заказа.

## 4. Содержимое

- название бизнеса;
- короткий номер операции;
- понятный русский статус;
- только необходимые контакты;
- безопасная ссылка на нужный workspace;
- без токенов, initData и внутренних ошибок.

## 5. Маршрутизация

- Используется production Mini App URL из конфигурации.
- Нельзя строить production-кнопку из request origin.
- Нельзя отправлять ngrok, localhost или 127.0.0.1.
- Для business-specific bot используется только явно настроенный bot context.

## 6. Идемпотентность

- Повтор статуса не создаёт лишнее уведомление, когда это возможно.
- Повторный webhook не создаёт второй заказ.
- Финансовое подтверждение отправляется один раз на первое решение.
- Сбой отправки логируется, но бизнес-операция сохраняется.

## 7. Privacy

- Клиент не получает внутреннюю заметку.
- Курьер не получает данные чужого заказа.
- Продавец получает только свой business scope.
- Полные платёжные реквизиты и proof не дублируются в сообщении без необходимости.

## 8. Fallback

Если web_app кнопка не отправилась, допустима безопасная bot link. Fallback не
может вести на preview или неизвестный домен.
